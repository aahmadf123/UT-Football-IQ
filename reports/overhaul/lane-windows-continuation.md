# Measured lane windows — 2026-10-21

The existing OL stage now derives source-linked opening/closure intervals and exact handoff/actual-entry widths from its actual `measured_lanes` producer. No new clear-width estimate, blocker body size, defensive occupancy, play-call gap, success label or trained model is introduced. These metrics remain experimental pending source-specific reviewed truth and the existing publication gates.

`gpu-worker/pipeline/lane_windows.py::lane_windows(tracklets, events, timeline=None, attacking_direction=None, *, lanes=None, threshold_yards=0.0)` consumes the actual original-gap LOS body/occupancy snapshots. `stage_oline` passes its already computed `clear_lane_width` rows; direct callers use the same real `measured_lanes` function. The source snap and geometry events need known matching shots, native clocks, qualified source evidence, complete occupancy and actual measured body extents. Known synthetic/stub/test source attribution cannot become a real lane observation. Unknown or conflicting carrier side prevents carrier-aligned output.

The explicit default opening definition is `width_yards > 0.0` at the measured transverse LOS section. It means that section contains a positive free interval. It does not establish that a runner fits, a continuous path is clear or a block succeeded. A supplied nonnegative analytical threshold is retained in the packet with its operator/definition; boolean, missing/nonfinite and negative thresholds refuse output. Every row preserves definition version `2026-10-21.1`, original gap subject, LOS/region, actual observation clocks and source event evidence.

Three append-only central definitions expose the results:

| Metric | Packet / unit | Behavior |
| --- | --- | --- |
| `gap_clear_timeline` | Composite `series`, `openings`, `closures`; `source_interval`; no aggregate scalar | Discrete measured widths, closed→open/open→closed time bounds, explicit left/right censoring. No exact transition time or continuous openness is invented. |
| `clear_lane_width_at_handoff` | `width_yards` / `yd` | Requires the explicit known carrier handoff and geometry at exactly that source clock. |
| `clear_lane_width_at_entry` | `width_yards` / `yd` | Reuses the actual continuous LOS crossing and original-gap classification from `observed_runs`; the measured section must exist at exactly the crossing clock and gap. |

Invalid or ambiguous snapshots become visible barriers, rather than zero widths. Duplicate clocks, unknown occupancy/source shots, unverified timelines and future nearby snapshots cannot justify an aligned value. Unlocated geometry clocks suppress transition intervals. Opening/closure endpoints are observation bounds, not a point estimate or a survival-analysis event time. There is no width interpolation. Event-aligned rows retain the actual carrier `tracklet_id`, including in the existing OL metric writeback.

`frontend/src/components/lane-window-visuals.tsx` is mounted in the existing team analytics surface for OL/RB/TE contexts. It shows discrete scatter samples, interval/censoring text, exact handoff/entry cards, the displayed LOS measurement region, a data table and film inspection at native source seconds. It independently verifies source event/shot/clock matching, ascending measurements, endpoint states relative to threshold, adjacency and invalid-sample barriers before rendering opening/closure labels. Missing snapshots remain unavailable.
