# Held-out source and category reliability drilldown

This continuation connects actual supported expected-outcome case diagnostics to the analyst/admin Learning screen. It does not reconstruct missing historical reports or generic classification case evidence. No new football labels, fitted features, weights, release qualification, or backend inference are introduced.

## Producer and immutable evidence

Worker `pipeline/expected_outcomes/diagnostics.py` produces versioned held-out case documents from the complete paired targets and actual model predictions. Cases retain task, source/full-media hash, session/game/canonical-play identity, prediction clock, subject, feature and annotation evidence hashes, observed outcome, prediction, signed error and frozen training-population baseline. The same task/canonical play cannot contribute twice through alternate views. Film categories are known only when the frozen manifest's reviewed, independently confirmed source-group membership actually matches the recording and media. Other category values stay unknown.

Both independent worker verification and backend release review reproduce the case document from the bound inputs. Backend review requires exact canonical content and the recomputed case SHA, including differences below aggregate floating-point tolerances. The global training baseline remains fixed when staff select a category; the holdout subset never fits a new baseline. The existing balanced release population and human decision gates remain separate.

Queued training stores checkpoint bytes under the full weights hash, report bytes under `models/expected_outcomes/<task>/reports/<report-sha256>.json`, and release evidence under `models/expected_outcomes/<task>/evidence/<evidence-sha256>.json`. Candidate UUID/version binds all three full hashes. Equal checkpoint bytes with different report or evidence bytes create a distinct candidate binding; an exact same-binding retry stays idempotent. Historical report/evidence bytes are not replaced by a later diagnostics revision. No existing stored record is rewritten by this change.

Queued training treats the requested local output directory as an execution container. Each job uses a safe UUID5-derived job child and each current runtime lease uses its positive integer attempt child. A new Retry job and a reclaimed lease attempt therefore preserve earlier fitted artifacts and can both proceed after publication failure. Unfenced direct adapter calls get a unique unleased child. The direct fit CLI and `train_manifest` retain their exact requested-directory exclusive-create contract; a replay of the same fenced attempt also refuses overwrite.

## Stored read and staff workflow

`backend/app/services/model_cases.py` stores the verified case document in a private evaluation-bound setting only after the current independent verification succeeds. Evaluation/model metadata contains the bounded descriptor rather than the full case table. Authenticated `GET /api/v1/learning/evaluations/<id>/cases` validates the stored descriptor/document/model/artifact binding, supports dimension/category/offset/limit filters, and serves an attachment with `download=true`. Supported dimensions are capture regime, source group, confirmed film category, observed outcome, fixed signed-error interval, and binary observed/predicted cell.

`frontend/src/components/model-reliability-cases.tsx` is mounted in the existing reliability panel. It provides actual category counts, selected descriptive losses/calibration/confusion/error distributions against the frozen baseline, paginated source cases, reload, and selected-case JSON download. Task, probability/yardage and signed-error units are explicit. Small slices show their sample counts and unavailable confidence intervals and cannot inherit a release badge. Raw candidate metrics cannot activate the persisted-evaluation endpoint. Unsupported historical and classifier reports explain that their source-case evidence is unavailable.

The downloaded selected-case document retains the full immutable case-table SHA and explicit filter. That SHA identifies the original complete case table, not the bytes of the filtered download. Cases retain typed source/evidence hashes for audit. The browser validates report/model/artifact identities, descriptor groups/counts, requested offset/page length, exact small-sample semantics and actual residual values before rendering.

Watch-source links require an exact match to a current trusted normal feature export: source/full SHA, session/canonical identity, native prediction clock, subject, feature evidence, active clip and current review revisions. Stale or unmatched historical cases remain readable with an explanation and disabled film action; there is no nearest-clip or nearest-time substitution. Valid links use exact clip-relative focus and preserve the actual Learning page query so Back restores report, source category and context. Unfiltered pagination also survives restoration.
