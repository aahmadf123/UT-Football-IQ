# Connected model reliability evidence (page 17)

The analyst/admin Learning screen now mounts `ModelReliability` next to its existing training workflow. It loads registered model versions and authenticated `GET /api/v1/learning/evaluations`, supports model/report selection and qualification filters, reloads actual API records and models, and downloads the selected stored record with model/version references. The download explicitly differs from the underlying report artifact bytes/checksum. No model execution occurs in the backend or browser.

The screen shows model/version, feature version when recorded, evaluation identity, artifact/report hashes, verification job and dataset identity. Current report binding requires the registered evaluation ID and exact registered artifact checksum. A historical or foreign-artifact report does not approve the current model. Candidate metrics remain explicitly unverified. Recorded gate results and human production approval are separate states; expected-outcome passing filters also require the recorded balanced 240 canonical plays, 12 independent groups, 80 plays/four sources per practice/coach-game/TV category and 20% adjudicated double labels. Small protocol fixtures cannot appear approved even if their numeric scores are good.

Actual stored diagnostics provide a model/baseline calibration scatter and count/mean table, paired loss/yardage errors against the documented baseline, fixed-bin signed-error counts, and observed-by-predicted confusion counts. Probability confusion uses an explicit recorded 0.5 threshold; classification confusion preserves actual abstentions. Exact bin counts must sum to the stored complete holdout sample count. Invalid counts, probability ranges, matrix dimensions or residual-bin continuity refuse the affected visualization. Regression does not acquire invented classes. Coverage appears only when actual eligible-example and prediction counts were recorded; complete prediction-conditioned P5 reports do not imply coverage of all film. Historical missing diagnostics and unavailable confidence intervals remain explicit.

For future reports, worker `pipeline/expected_outcomes/diagnostics.py` and backend `app/services/model_diagnostics.py` compute only descriptive statistics from already heldout paired predictions/targets. Signed-error intervals are fixed and versioned (`diagnostics_version=1`), not fitted against test outcomes. Binary edges are -0.5/-0.1/0/0.1/0.5 probability error; yardage edges are -10/-5/-2/-1/0/1/2/5/10 yards, with open outer tails and lower-inclusive/upper-exclusive boundaries. Backend release statistics independently reproduce the diagnostics and compare the exact hash-bound report; edited counts fail evidence review. Existing classification evaluation stores actual class confusion including abstentions. The new diagnostics do not change model parameters, feature schema, prediction clocks, split rules, calibration gates or human promotion requirements. Older expected-outcome candidate artifacts without this diagnostic schema require a freshly produced report before the strict current release reader can accept it; historical stored records remain readable with explicit gaps.
