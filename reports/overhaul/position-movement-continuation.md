# Observed position movement continuation

Date: 2026-10-21. Branch: `codex/overhaul-completion-20261021`.

This implements the remaining observed position products from overhaul pages 15–16. All new rows remain experimental. This is implementation and contract verification, not football accuracy validation, model approval, external held-out evaluation, or production publication.

## Implemented products

| Metric | Computation and limits |
| --- | --- |
| `observed_separation` | Native-time receiver/opponent distance series and paired measured paths. Comparison is explicitly selected or labeled `nearest_observed_defender`; coverage responsibility is never inferred. Scalar is the minimum supported distance. |
| `get_off_time` | Qualified first-movement event minus qualified snap for an explicitly participating defender. No movement event means unknown. This is not recognition or assignment quality. |
| `observed_rush_path` / `observed_pursuit_path` | Path length plus calibrated source trajectory for explicit defensive pass-rush/pursuit participation. Roles alone do not establish participation. |
| `observed_closing_speed` | Signed decrease in distance divided by elapsed native source time against one explicitly selected opponent. Negative opening rates remain negative. Series retains each supported interval; scalar is the interval mean. No tackling quality is inferred. |
| `operation_time` | Qualified linked snap-to-kick/punt interval; continuous visible same-shot kicker image observations are required only through the kick. Field calibration is unnecessary for temporal timing. |
| `hang_time` | Qualified linked kick/punt-to-landing interval for the same continuously visible ball in the same known shot. A kicker leaving view after kicking does not invalidate ball-flight timing. Airborne image observations are retained as `ball_observations`, never projected into a ground trajectory. |
| `kick_landing_location` | Explicit qualified landing field coordinates with safe calibration and measured attacking direction. It is a spatial packet with no scalar summary. |
| `te_usage_transition` | Explicit qualified block/chip/route states for one TE, interaction and observed opponent. Permitted transitions are block→route, chip→route and block→chip→route. Contact, participation and states are never inferred from closeness. |
| `position_opportunity` | Separate rep=1 row from qualified explicit participation and resolved player/role/team, even when trajectory, calibration, direction, end time or outcome measurement is unavailable. Consumers deduplicate using the authoritative canonical play, player and opportunity kind. Unknown identity does not create a player denominator. |

Spatial observations require finite calibrated field samples, explicit role/team, measured direction, native PTS, explicit observed visibility and the same known camera shot. Continuity is at most 200 ms. Hidden/unknown samples, cuts, conflicting duplicate samples and missing native timestamps cannot be bridged. Supported geometry prefixes retain `partial_observation=true`, `measurement_complete=false`, `right_censored=false` and an explicitly scoped scalar summary; they are film evidence, not complete scalar aggregates. Duration censoring remains separate. Absent observations are not completed zeros. Duplicate or missing track IDs reject ambiguous new products. An explicitly unverified FPS-fallback timeline is rejected.

## Qualified input and actual ingestion

The new module is `gpu-worker/pipeline/observed_position_products.py`, called by `stage_metrics.run`. The existing QB, OL and run helpers are preserved. Metric definitions remain in the single backend `metric_definitions.py` registry, including explicit scalar keys and a null scalar key for landing geometry.

`position_participation` has an event ID, source timestamp, and attributes `actor_id`, `opportunity_kind`, `end_seconds`, `shot_id`, and measured `attacking_direction` for spatial products. Optional `opponent_id` selects a comparison. Opportunity kinds are routes, pass_rush, pursuit, coverage, blocking_reps, punts, kickoffs or field_goal, with role/team checks. A missing end remains sufficient for an explicit player opportunity but not an outcome trajectory. Qualified means human/manual, or approved artifact-bound model evidence under the existing `position_evidence.qualified` contract; a validated boolean alone is insufficient.

The actual orchestrator had two ingestion gaps, now fixed with regression tests through `run_pipeline`'s real correction acceptance path:

- Multi-actor participation, role observations, TE states, movement and kicking events now retain distinct observation IDs. Retrying an ID replaces that observation. Unknown or invalid interval clocks invalidate only the corresponding multi-observation ID, preserving other actors/states/operations. Scalar snap correction behavior is retained.
- A participation event with a timestamp and end_seconds can derive its interval start from that timestamp. Clip intervals convert to source recording time once, including nested boundaries.

Role trace found that `stage_labels` enriched team/side but had no producer for `observed_role` or `role_resolved`. A qualified hydration adapter now runs before metrics, OL and expected-outcomes stage inputs. It accepts `position_role` events or participation events declaring `actor_id`, `observed_role`, `team_label`, and a native timestamp/known shot. It also accepts reviewed `position_roles` label assignments scoped to existing actor tracks. Conflicting current roles become unresolved. The adapter never uses roster position to infer observed role and never fills player identity. Movement packets retain role evidence.

Existing explicit player_id inputs with absent identity flags remain a legacy staff/manual compatibility input, per the root integration decision. They do not gain new identity approval. Explicit unresolved/candidate/conflicting/unapproved identity states are rejected for opportunity rows; backend identity and publication qualification remains authoritative.

## Reachable staff workflow

Backend `event_tag` corrections already accept an arbitrary named event and attributes, with revision history and human/manual provenance. The prior Clip Review timed-event form exposed only basic event names and timestamps, so it could not author the required role/participation evidence.

`frontend/src/app/clip-review/corrections-panel.tsx` now provides:

1. Open a current play in Clip Review, select **Fix something**, then **Record position observation**.
2. Choose an existing overlay actor track, a known source camera shot and the observation's play time. Unknown shots cannot be invented through this form.
3. For role/participation, explicitly choose side and observed role. For participation choose a compatible opportunity, end time, optional measured attacking direction and comparison actor.
4. For TE states choose state, existing comparison actor and shared interaction name. For snap/kick/punt/landing use the shared kicking operation name; ball observations use an existing ball track, and landing accepts measured field coordinates.
5. Save using the existing revisioned correction API. The orchestrator converts the play clock to the native recording clock on reprocessing. Player identity is corrected separately; writing a role does not assign a roster identity.

This form writes the same event contract consumed by the producers, without raw JSON or a new endpoint. No API schema change was necessary. Kicking products remain unavailable when the film/approved producers do not supply an actual continuous ball track; the form does not create one.

No hull, image-box body width, protection outcome or assignment inference. |
