# Coaching Summary report template

`report_type = "coaching_summary"` — generated by `POST /api/v1/reports`,
rendered by `backend/app/reports.py`. Replaces the legacy client-side text
blob with a real, server-backed export (Issue #111).

## Output formats

| Format | Content type        | Renderer        |
| ------ | ------------------- | --------------- |
| `pdf`  | `application/pdf`   | `reportlab.platypus` titled multi-section document |
| `csv`  | `text/csv`          | stdlib `csv.writer` with per-section rows |
| `json` | `application/json`  | snapshot of `CoachingSummaryData` |

All three formats are produced from the same `CoachingSummaryData` snapshot
so they stay in sync.

## Sections

The same labels appear in the frontend Report Builder UI. A POST body may
include any subset via the `sections` field; omitting it includes everything.

| Section                       | Data source                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| Self-scout exposure           | `clips.personnel_grouping` — clip count grouped by personnel grouping (NULL → "Unknown")             |
| Position group development    | `players.position_group` — count of active players per group                                         |
| Model quality                 | `clips.is_reviewed`, `coach_corrections` count, `avg(clips.confidence)`                              |
| Opponent prep package         | `videos.opponent_team` — film count per opponent                                                     |

Every output also includes a Totals block: total videos, total clips, active
players, reviewed clips, coach corrections.

## RBAC

- `POST` / `GET (single)` / `GET (download)` — coach, analyst, or admin
  (`require_coach_or_above`). Non-staff users see only their own reports.
- `GET (list)` — admins/analysts see every report; coaches see only their own.

## Storage

Generated artifacts land in the `S3_BUCKET_ARTIFACTS` bucket under the key
`reports/{report_id}.{ext}`. The download endpoint mints a presigned GET URL
with TTL = `S3_PRESIGN_TTL` (default: 1 hour).

## Adding a new report type

1. Add a new constant to `app/reports.py` (e.g. `REPORT_TYPE_HEALTH_SUMMARY`).
2. Implement an `aggregate_*` async function that returns a
   `CoachingSummaryData`-shaped object.
3. Map the type in `routers/reports.py::create_report` and the background
   task dispatcher.
4. Add a markdown file in this directory documenting the new template.
